# 職歴トレースの作り直し 設計

親の設計書: `docs/superpowers/specs/2026-11-18-portfolio-site-design.md`（以下「親スペック」）。この文書は、親スペックのうち職歴トレース（Career）の見た目と動きを置き換える。ここに書いていないことは親スペックに従う。

モック: `docs/superpowers/specs/mockups/trace-a.html`（トレース部分だけを実データ10行で再現した使い捨てのモック。詳細の中身は仮の文）

## 目的と理由

v1/animationまで実装したところで、本人がページを見て「職歴のグラフにもう少しこだわれないか」「アニメーションの使い方をゼロベースで考え直したい」と感じた。トレースは親スペックで「ページで唯一の大胆な要素」と決めた部分だが、チャートとして見直すと次の弱さがあった。

- バーが細く、右側の大部分が空白で、主役のはずのバーが脇役に見える
- 目盛りが上端の年の数字だけで、バーの位置から年を読み取れない
- 親（freee）と子（役割）のバーが同じ太さと色で、親子の違いがバーの側で見えない
- いちばん古いエクストップがいちばん下にあり、freeeと時期が重なるACALLも下にまとめられていて、時系列と重なりが読めない
- 「今も続いている」ことを示すのが終端の小さな点だけで、「現在」を示す線がない
- 読み込み時の動き（目盛り、バー、終端の点）が3つの別々のアニメーションで、時間の流れという意味を持っていない

本人の方針は「モダン・ミニマル」。トレースというコンセプトは変えず、本物のトレース表示に寄せてチャートとしての読みやすさを上げ、動きは時間の流れを見せる1つの動きにまとめる。

## ゴール / 非ゴール / アンチゴール

- ゴール: バーの位置から年が読める。親子と会社の違いがバーの側でも見える。会社が開始順に並び、重なりが読める。各spanの長さが一目でわかる。読み込み時の動きが「2015から現在までの時間の流れ」として1つにまとまっている
- 非ゴール: トレース以外の節の見た目、文面、データの形は変えない。`/play`のような遊び用の動きはv1に入れない
- アンチゴール: 装飾が増えてうるさくなる（モダン・ミニマルから外れる）。動きのせいでLCPやCLSが悪くなる。JSが無効なときや読み込みに失敗したときにバーや文字が見えなくなる

## 制約

親スペックの制約をそのまま守る。特にこの変更に関わるもの:

- 自動で動くのは読み込み時の1回だけ。自動で動かすのは`transform`と`opacity`だけ。名前と価値提案は動かさない
- 出現のために要素を隠す処理はJSでだけ行い、CSSとprerender済みのHTMLには隠す指定を書かない。reduced-motionでは最終状態で止める
- 色は親スペックのトークンだけを使う。新しい色は足さない。書体の太さは400と700だけ
- 画面の文字はすべてLINE Seed JPのサブセットに入る（ビルドが欠字で失敗する仕組みはそのまま）
- 印刷では装飾を消し、閉じた行の中身も出す

## 検討した方向

| 方向 | 内容 | 判断 |
| --- | --- | --- |
| A. 本物のトレースに寄せる | 目盛り線を全行に通す、「現在」の線、親子でバーの太さを変える、spanの長さを書く、会社を開始順に並べる、再生ヘッドの動き | **採用**（本人が選択）。コンセプトを深める方向で、動きも1つにまとまる |
| B. 年表として読ませる | ラベル列をなくして役割名をバーに直接書き、出来事を注記する | 不採用。トレースのコンセプトから離れ、注記は新しい文面になる |
| C. 今の形のまま磨く | 目盛り線、太いバー、並び順だけ直す | 不採用。変更は小さいが「こだわった」印象が弱い |

## 決まった設計

### 並び順

- 会社の行を開始の古い順に並べる: エクストップテクノロジー（2015.04）→ freee（2015.11）とその役割 → ACALL（2018.08）
- 会社の配下の役割は、今と同じく会社の行の直後に開始の古い順で並べる
- 行の種類（parent / child / other）と行数（10行）は変えない。変わるのは順番だけ

### バー

- 会社の行（parent、other）のバーは太く（約14px）、役割の行（child）のバーは細く（約6px）する。色は今と同じ（freeeとその役割は`span`、ほかの会社は`span-soft`）
- バーの右端は「終了月の終わり」にする（今は終了月の初めで止まっていて、1か月短く見える）。続いているspanの右端は、ビルド時の月（`__BUILD_MONTH__`）の終わり
- 続いているspanの右端には、今と同じく`open`色の点を置く

### 目盛り線と「現在」の線

- 2年ごとの縦の目盛り線を、すべての行のバーの帯に通す。モバイルでは4年ごとに間引く（親スペックと同じ）
- 目盛り線は、トレース全体にかぶせる1枚の重ね絵ではなく、各行のバーの帯の背景として引く。モバイルでバーがラベルの下に回っても、線がラベルの文字に重ならないようにするため
- 「現在」（ビルド時の月の終わり）に点線を1本引き、軸の上端に「現在」（英語版は"Now"）と書く

### spanの長さ

- 各バーの右端のすぐ後ろに、spanの長さを書く。置き場所は全行で同じ（バーの右）
- 「現在」の線の右に、長さを書くための余白の列を設ける（モックではデスクトップ5.5rem、モバイル4.5rem）。現在まで続くバーの長さもこの列に収まる
- 点線をまたぐ文字は、文字の背景を地の色にして線を切り、読みやすくする
- 表記は日英とも同じ短い形: `3y 8m`、`7m`、`3y`。続いているspanも、ここまでの長さを同じ形で書く（例: `11y 1m`）。「続いている」ことは終端の点と「現在」の線が表すので、言葉では足さない
- 長さは両端の月を含めて数える（2015.04〜2015.10は7か月、2015.11〜2019.06は3年8か月）
- 色は`muted`の1色、太さは400、大きさは13px。数字だけを塗り分けたりはしない
- 長さはラベル列の期間（`2019.07 – 2022.06`）から計算できる補足なので、支援技術には読ませない（`aria-hidden`）

### 動き

- 読み込み時に、縦の「再生ヘッド」が2015から「現在」の線まで流れる（モックでは約2.6秒、ゆっくり始まってゆっくり止まる動き）。各バーは、ヘッドが通過した分だけ左から伸びる
- 再生ヘッドの位置を1つの値として動かし、各バーの伸び具合（`scaleX`）、長さの文字と終端の点が出るタイミングは、すべてその値から計算する。バーごとに遅延や長さを足し算で決めない
- 長さの文字と終端の点は、ヘッドがそのバーの右端を通過したときに`opacity`で現れる
- ヘッドが「現在」に着いたら、ヘッドは消えて「現在」の点線が残る
- 親スペックの「目盛り線が引かれ、各スパンが開始年の順に伸び、最後に終端が灯る」という3段の動きは、この再生ヘッドの動きに置き換える
- `<details>`の開閉の動きは今のまま（親スペックの「動き」のとおり）
- reduced-motionのときは、ヘッドを出さず、すべて最終状態で表示する
- 印刷では、ヘッドと目盛り線を出さない

### 実装の細部（設計時に決めたこと）

レビューで出た疑問に、設計の側で答えておく。いずれも設計者の判断で、本人の承認事項ではない。

- 位置の計算: 横軸は今と同じ2015〜2027のまま。バーの左端は開始月の初め（`toYearFraction(start)`）、右端は終了月の終わり（`toYearFraction(end) + 1/12`）。閉じたspanも続いているspanも同じ規則にする。続いているspanの右端と「現在」の線と再生ヘッドの終点は、すべて`toYearFraction(__BUILD_MONTH__) + 1/12`
- 長さの文字はビルドのたびに変わりうる（続いているspanの長さは`__BUILD_MONTH__`で決まる）。これは続いているバーの幅が今もビルドの月で変わるのと同じで、意図どおり。単体テストは今と同じく`now`を引数で渡して固定し、e2eは長さの文字を検証しない
- 並び順の規則: 会社の行を開始月の古い順に並べ替える。開始月が同じ会社はデータの順のまま。会社の配下の役割の並びは今の規則（開始の古い順）のまま
- 目盛り線と「現在」の点線は、どちらも各行のバーの帯（と軸の帯）の背景として引く。軸の帯の上端に「現在」の文字を置く
- 再生ヘッドは、トレース全体にかぶせる1つの要素にする（動いている間だけ見える一時的な線なので、モバイルでラベルの上を通っても構わない）。位置は`transform: translateX`で動かす
- 動きは、anime.jsで普通のオブジェクトの値（ヘッドの位置）を1つだけ動かし、`onUpdate`の中で各バーの`scaleX`と、長さの文字と終端の点の`opacity`を書く。最初に隠す処理（`scaleX(0)`、`opacity: 0`）もこのJSの中でだけ行い、reduced-motionのときは何もしない。アニメーションの終わりに、インラインの指定を外してprerender済みの最終状態に戻す
- 余白の列: バーの帯に右の余白（`margin-right`）を取り、バーの位置の割合は、その余白を除いた幅に対して計算する。長さの文字はこの余白の列にはみ出してよい
- 文字: 「現在」はすでにページの期間の表記で使っているので、サブセットに入っている。英語版の軸の上端は"Now"（英語の文面と一緒に承認を取る）。`3y 8m`の数字と単位の間は空けず、`y`と`m`の後ろは普通の半角空白にする。サブセットに入っていない文字があればビルドが失敗するので、そこで気づける

## 親スペックから変わる箇所

- 「ビジュアル方針」のワイヤーフレーム: 会社の並び順、目盛り線、「現在」の線、spanの長さを足した形にする
- 「ビジュアル方針」の箇条: 「バーの位置は全行で揃えたまま」は維持。「デスクトップでも、役割名の横に期間を文字で出す」も維持し、それに加えてバーの右に長さを書く
- 「動き」の1つ目の箇条: 再生ヘッドの動きに置き換える
- 「アニメーション（anime.js v4）」の箇条: 変えない（scopeとreduced-motionの扱い、隠す処理はJSだけ、など）

## 影響するテストと計画

- Task 3の`buildTraceRows`の並び順のテスト（`['parent', 'child', …, 'other', 'other']`）は、新しい並び（other、parent、child×7、other）に合わせて書き直す
- バーの右端を終了月の終わりにするので、Task 3の位置のテスト（現職の右端が`positionPercent(now)`に一致する、など）も合わせて直す
- Task 4の描画テストとTask 6のe2e（バーが最終状態に落ち着く、reduced-motionで動かない、JS無効でバーが見える）は、新しい動きでも同じ性質を守る
- Task 7の重さの上限（JS、CSS、フォント）は、作り直したあとに測り直す。長さの表記で使う`y`と`m`はすでにサブセットに入っている

## builderに任せること

- 再生ヘッドの長さとイージング（モックの約2.6秒、`inOutSine`を目安に、見た目で決める）
- 余白の列の幅、点線と文字の細かい位置
- 再生ヘッドと点線の線の太さと色（親スペックのトークンの範囲で）
- スタックのどこに入れるか（下の層を直すか、上に新しい層を積むか）は、計画で決める
